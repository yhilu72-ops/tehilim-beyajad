# Resultado de los ocho pendientes

## Mercado Pago

El entorno real no se activó y no se realizó un cargo. Hay registros históricos aprobados sin metadatos suficientes para certificar un pago real. La preferencia autenticada, los precios y las protecciones de producción tienen pruebas automatizadas; no equivalen a una prueba de compra completa. La sesión no dispone de conexión a la cuenta de Mercado Pago para activar credenciales reales.

## Contraseñas y eliminación

Prueba HTTP real con una cuenta temporal dirigida a un alias de Gmail del titular: registro 200, recuperación 200, correo recibido, enlace de recuperación 303 con sesión válida, cambio de contraseña 200, login con contraseña nueva 200. Se corrigió una carrera que cambiaba el hash antes de que Supabase procesara el token.

**Bloqueo confirmado:** Supabase redirigió el enlace a `http://localhost:3000`, aun solicitando la URL del sitio. En Authentication → URL Configuration debe configurarse Site URL como `https://tehilim-beyajad.vercel.app` y permitirse `https://tehilim-beyajad.vercel.app/**`. La conexión Supabase disponible no tiene una operación para cambiar esa configuración. No se declara terminado el recorrido de recuperación en la interfaz hasta corregir y repetir este paso.

La eliminación falló por falta de permisos de tablas del rol servidor. Se corrigieron los permisos mínimos, se repitió el endpoint con resultado 200 y se verificó que quedan cero cuentas con el correo temporal. No se cambiaron contraseñas ni se borraron cuentas existentes del titular. Los mensajes de prueba permanecen en su Gmail.

## Shabbat

La interfaz usa `tbj_seat_reserve/list/confirm/complete` con `read_mode=shabbat`, sin inserciones directas ni fallback al modo normal. Prueba transaccional en Supabase con dos identidades sintéticas: rechazo de capítulo ocupado, visibilidad de reserva ajena sin ID del autor, imposibilidad de completar la lectura ajena, confirmación de la propia y separación del modo normal. Todo revertido con rollback. No equivale a una prueba con dos teléfonos ni a una prueba de concurrencia de carga.

## Privacidad de peticiones

La tabla original solo puede leerse por su autor. La función pública de consulta devuelve cuatro campos: id de petición, categoría, nombre permitido y nota permitida. Anónimo no devuelve nombres reales; iniciales no devuelve nombres completos; ambos omiten detalles libres. No devuelve usuario, dispositivo ni nombre de madre por separado. Se comprueba el bloqueo del autor. Prueba real de RLS aprobada.

La aplicación consulta esa función y no presenta peticiones locales no guardadas como publicadas. Si no hay otra petición, lo informa; ya no asigna una persona de la lista histórica en ese recorrido. Al cerrar sesión se limpian las asignaciones locales.
